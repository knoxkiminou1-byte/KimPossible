      How I build

      Research. Architecture. Build. Test. Evidence.

      Engineering judgment matters as much as the toolchain.

      Build model: Primarily human code, with AI-ready code and deliberately AI-assisted experiments when the point is to test what current models can do inside a real system. When AI is part of the work, I say so. The goal is to show companies both hands-on engineering craft and the judgment to use AI where it actually adds leverage.
      01

      Recover

      Find the real source, repo, deployment, constraints, and proof before changing architecture.

      02

      Model

      Turn the business problem into entities, states, rules, permissions, and failure paths.

      03

      Build

      Write and assemble the system primarily with human code. Use AI-ready code or AI-assisted experiments when the build is intentionally testing model capability, workflow fit, or a company use case.

      04

      Verify

      Test logic, keyboard paths, mobile layouts, console state, external links, and the real destination system.

      Serious builds / collaborations

      If the system matters enough to inspect, test, and defend, bring me the problem.
